Scene 1 / 8 · Overview

The whole platform, two of almost everything

Red Hat's tested container enterprise topology for AAP 2.7. Each component runs in Podman containers on its own RHEL VM. An external HAProxy fronts the gateways, and shared state lives outside the services in PostgreSQL and Redis.

  • 2 VMsPlatform gateway, behind an externally managed HAProxy
  • 2 + 2 + 2Automation controller, automation hub, Event-Driven Ansible, all active-active
  • 1 + 2Hop node and execution nodes form the automation mesh
  • 6 RedisCluster mode, colocated on the gateway, hub and EDA VMs
  • 1 VMMetrics service (single instance in the tested topology)
  • ExternalPostgreSQL 15, 16 or 17, customer-provided and managed

The RPM installer is gone in 2.7, so containerized is the RHEL install path. Multiple hubs need shared content storage.

Scene 2 / 8 · Ingress

Any gateway can answer any request

HAProxy health-checks both gateways and spreads UI and API traffic across the healthy ones. The gateway keeps settings, sessions and JSON web tokens in Redis, not in local memory, so a user can land on either instance.

  • :443HAProxy to platform gateway
  • EnvoyThe gateway proxies to controller, hub, EDA and metrics over HTTPS (NGINX on 8443, 8444, 8445)
  • ScaleAdd gateway VMs to the inventory and the HAProxy backend pool

HAProxy itself is outside the installer. Make it redundant (a keepalived pair or a cloud load balancer) or it becomes the single point of failure.

Scene 3 / 8 · Automation controller

Controllers run active-active

Every control node serves the API and can schedule work. Scheduling is coordinated through the database, so there's no leader election to fail over. Control nodes hand jobs to execution capacity and record their events.

  • Task mgrDecides which pending job runs on which instance group
  • DispatcherRuns background tasks, including controlling each job
  • CallbackCallback receiver writes job events to PostgreSQL
  • ReceptorSubmits work to the mesh on TCP 27199

The capacity bar on each controller is control capacity. Execution capacity sits on the mesh nodes and scales separately.

Scene 4 / 8 · Automation mesh

Jobs travel the mesh

Receptor links controllers to execution nodes over TCP 27199, in both directions. The hop node relays work into a segment the controllers can't reach directly, such as a DMZ. Each job runs in an execution environment container, and its events stream back the same way.

  • DirectController → Execution 1
  • RelayedController → hop → Execution 2
  • HopNetwork latency matters more than CPU or RAM on hop nodes

The tested topology has one hop node. Anything that peers only through it loses its route if it fails (try it in scene 7).

Scene 5 / 8 · Database

PostgreSQL HA is yours to build

Gateway, controller, hub, EDA and the metrics service each keep their own database. In the enterprise topology PostgreSQL is externally managed: AAP connects to one endpoint and doesn't run replication or failover itself.

  • ReplicateStreaming replication from primary to standby
  • EndpointOne stable VIP or DNS name that follows the primary
  • OptionsPatroni, EDB Postgres, or a managed service such as Azure Database for PostgreSQL with zone-redundant HA
  • LocalityKeep the database in the same location as the AAP VMs

Step 2 · primary fails

Your HA layer promotes the standby and moves the endpoint. AAP services reconnect. Expect a short API outage, and anything writing during the switch fails.

Scene 6 / 8 · Redis

Redis holds sessions and event queues

Cluster mode needs six Redis nodes, three primaries and three replicas, colocated here on the gateway, hub and EDA VMs. The gateway stores settings, sessions and tokens. EDA uses it for event queues and job launching. Their data is partitioned from each other.

  • :6379Gateway and EDA to Redis
  • :16379Redis cluster bus, node to node
  • PlacementAny component VM except execution nodes or the database, or dedicated VMs

External Redis isn't supported for containerized AAP. Standalone mode is a single Redis with no automatic failover.

Scene 8 / 8 · Recovery

Recover, rejoin, zoom out

The failed component comes back, passes its health checks and rejoins. Some roles don't swap back: an old database primary returns as the standby, and an old Redis primary returns as a replica.

  • IngressRedundant HAProxy pair in front of two or more gateways
  • MeshTwo hop nodes per network segment you route into
  • DatabaseTested failover behind one stable endpoint
  • RedisCluster mode across six nodes
  • HubShared storage for content across hub nodes
  • DrillRehearse each failure above in a non-production stack
